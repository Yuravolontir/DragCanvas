# DragCanvas: карта кода для изучения
Этот файл задаёт порядок чтения проекта и правила «учебного» кода. Он не
заменяет комментарии в исходниках: это карта, которая объясняет, где искать
нужную часть системы.

## Как проходит один пользовательский запрос

```text
React-страница (`src/`)
  -> `apiFetch` (`src/api.js`)
  -> Express (`server.js`)
  -> общий API-router (`routes.js`)
  -> router функции (`features/<feature>/*.router.js`)
  -> controller: проверка запроса и HTTP-ответ (`*.ctrl.js`)
  -> model: SQL и база данных (`*.mdl.js`)
```

## Порядок изучения

1. `src/main.jsx` — запуск React.
2. `src/App.jsx` — таблица страниц и их URL.
3. `src/UserContextProvider.jsx` и `src/api.js` — пользователь, вход и запросы.
4. Самостоятельные страницы в `src/`.
5. `src/editor/CreateNewProject.jsx` — оболочка редактора.
6. `src/editor/Landing/` — элементы конструктора.
7. `src/utils/` — преобразование проекта, экспорт и адаптивность.
8. `server.js` и `routes.js` — запуск backend и распределение запросов.
9. Каждая папка `features/` в порядке router -> controller -> model.
10. `services/`, `middlewares/` и `jobs/`.
11. `tests/` — примеры ожидаемого поведения системы.

## Где что лежит в редакторе

- `src/editor/Landing/Viewport.jsx` — три раскладки редактора (широкая, ящики,
  телефон); сам холст — в `EditorCanvas.jsx`.
- `src/editor/Landing/Toolbox.jsx` — панель элементов, `Toolbox.styles.js` — её
  оформление. Тот же приём (`*.styles.js`) используется для `Header`, `Resizer`,
  `Carousel`, `AIAssistant` и `Toolbar/ToolbarRows`.
- `src/editor/Landing/Toolbar/useRowProp.js` — общие операции над списком
  записей, которыми редактируются девять элементов.
- `src/useAiSiteGenerator.js` — весь диалог с генератором; `AIAssistant.jsx`
  только рисует панель.

## Экспорт страницы

`src/utils/exportToHtml.js` собирает один HTML-файл и делится на три части:

- `utils/export/converters.*.js` — по функции на элемент: узел -> разметка.
- `utils/export/sheet.js` — стили и факты о странице, накопленные по пути.
- `exportToHtml.js` — порядок шагов и сам документ.

Мелкие помощники лежат рядом: `values.js` (цвета, отступы, экранирование),
`images.js` (адреса картинок), `nodes.js` (обход дерева, анимация, адаптивность).

## Правила учебного кода

- Имя функции должно говорить, что она делает: `restoreVersion`, а не `run2`.
- Один смысловой шаг занимает отдельный блок; длинный JSX не пишется в строку.
- Перед сложным потоком объясняется причина решения, а не перевод синтаксиса.
- Сложное выражение разбивается на промежуточные переменные.
- Состояния React группируются по назначению.
- Повторяющийся интерфейс выносится в небольшой именованный компонент.
- Router только связывает URL и controller; controller отвечает за HTTP;
  model отвечает за базу данных.
- Ошибка, загрузка и отсутствие данных являются явными состояниями UI.
- Рефакторинг не меняет API или поведение без отдельной причины и теста.

## Что не переписывается ради оформления

- `node_modules/` — сторонний код.
- `dist/` — результат сборки.
- `scripts/templates-out/*.json` — сгенерированные данные.
- SQL-миграции — исторические операции над схемой; к ним добавляются пояснения,
  но уже применённый SQL не форматируется массово.
- Большие объекты шаблонов — это данные дизайна, а не алгоритмы. Для них важнее
  комментарий к структуре и builder-функциям, чем комментарий к каждому числу.
